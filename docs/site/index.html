PION/1

A one-bit oversampled synthesizer on the Raspberry Pi Pico.

  • Word rate 15 625 Hz
  • Quarter cycle 2048 bits
  • Full cycle 8192 bits
  • Base frequency 61.04 Hz

01 Everything is a bit

PION/1 has no 16-bit samples and no 24-bit accumulators. Every voice produces a stream of bits, every control parameter is a number of slots, and the analog front end reconstructs the waveform from nothing but the density of ones in that stream.

It runs on an RP2040 at exactly 500 000 bits per second — one bit every 2 µs. A 32-bit word is therefore 64 µs of audio, and the word rate is 15 625 Hz.

02 Three ideas

The oscillator is a bit stream

The waveform is a 2048-bit quarter cycle, generated by running a first-order delta-sigma modulator over a quarter sine. A full cycle is 8192 bits, so the base frequency is 61.04 Hz.

The generator measures the density discontinuity at all three mirror joins and fails the build if it exceeds 2% of full scale.

Level is a slot count

Each output word has 32 slots. A voice's level is the number of slots it owns. Louder voices take slots from quieter ones, and the slots nobody owns fall back to the idle pattern — the floor of the signal.

This is bit-stealing, and it is the only way to control the level of a 1-bit signal without an amplitude field.

Rotating masks kill the aliasing

Every mask rotates right by one bit each word. The arrangement between the voices stays fixed while their absolute position drifts, which turns the aliasing tones of a static mask into broadband noise.

The re-modulator

Reading a captured stream at an arbitrary rate is the subtle part. PION/1 counts the ones in a sliding window, then re-quantises that count back to a single bit with a first-order feedback loop: 

err += (count - L/2) - (out ? +L/2 : -L/2)
out  = (err >= 0)

In the count domain a full-scale window of L ones is L, so the output bit contributes ±L/2 — exactly like the window average does. The loop therefore drives the density of the output bits towards the density of the input window. The level is preserved; only the shape is quantised.

03 Build it

Firmware

export PICO_SDK_PATH=~/pico-sdk
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build -j

The result is build/PION1.uf2. Either drag it onto the Pico in BOOTSEL mode, or let the helper do it — it waits for the bootloader, copies the UF2 and waits for the console to come back: 

tools/pion1_flash.sh

A running PION/1 can also be dropped into the bootloader over USB, so you never have to reach for the buttons: 

picotool reboot -u -f

The console

The console is USB CDC, and the host finds it by a stable name rather than by whatever ttyACM number the kernel happened to hand out: 

python3 tools/pion1_console.py

The port is /dev/serial/by-id/usb-Raspberry_Pi_PION-1-if00.

Host tests

The DSP core has no Pico SDK dependencies, so it compiles and runs on the host. That turns “it builds” into “it produces the right numbers”. 

cmake -B tests/build -S tests -DCMAKE_BUILD_TYPE=Release
cmake --build tests/build -j
./tests/build/test_dsp

Render a WAV

The renderer uses exactly the same DSP code as the firmware, so you can hear what the hardware will produce before it exists. 

./tests/build/render_host --freq 440 --seconds 2 --out tone.wav

04 Status

An early release. The signal chain is complete and covered by a host test suite that checks the actual signal rather than just the code paths.

  • DSP core — sine table, mixer, resampler and FM voice, checked by 55 host tests that measure the signal.
  • Console — speaks USB CDC and greets you whenever you attach; the host finds it by a stable by-id path.
  • User interface — a handful of keystrokes, not a real interface.
  • Sampler — does not yet track the DMA write position, so it reads the whole capture ring rather than the newest audio.
  • Analog front end — not yet built; every timing figure in the documentation is calculated, not measured.
